## Your task: `reverb-zones`, the level's per-area reverb

The SPU reverb itself is ported (task 725, `spu-gaussian-reverb`), but the levels' reverb zones are not:
the port does not switch the reverb preset/depth as Bond moves between areas (the README roadmap lists
"sound reverb" as open). Find in the decompile how a level selects reverb per area (the cel/room or
volume data that carries it, the function that applies it on the SPU, the fade between presets), document
it in `docs/systems/` first, then port it with tests that pin the zone for known positions on two levels
(one indoor/outdoor pair). Tests are silent (`NF_SILENT=1`).

**No drawing**: the main agent draws every page (it compares each against PCSX2). You deliver the data, the state,
the flow and getters the draw code can call, in `crates/nf-view/src/menu.rs` (`FrontEnd`, `Page`, `action()`) or
`nf_game` as fits, with docs first (`docs/systems/<name>.md`, addresses + evidence tags) and tests (numbers/ids only,
ISO-gated where they read the disc, each with a sister assertion that can fail).

**Tests pin only proven behaviour.** Every assertion about what the game does cites its evidence: [M] a decompile
address that actually says it, [D] disc bytes, or [L] a live PCSX2 measurement from a FRESH boot (a save-state resume
skips the boot path). A guess, a port choice or an [S] item is never a hard assertion: mark it `// [S] unverified` and
keep it out of pass/fail. If an existing test contradicts the decompile, the TEST is wrong: fix it, with the address, and
say so in the report. Never weaken a decompile-backed test to make code pass.

**Run the crates your tests touch before pushing**, and report what you ran.
