# 07000009 — Night of the Agent (Tower A, `UpdateMFX_03TowerA` 0x113558)

The Tower mission's first level: Bond infiltrates the Phoenix Building's underground car park at
night in the rain and reaches the main lift to the office floor. 40 maps, 151 objects, 288
placements, 6 drones, 120 collision cels [D `nf-extract level-survey`]. The music updater is keyed
0x07000006 too (`UpdateMFX_03TowerA` reads `*(int*)MapMusicData != 0x07000006` [M 0x113558:36]).

## Route (car park → lobby → lift)

1. Bond spawns in the car park (y ≈ −377) next to the Phoenix van (PheonixVan_Exterior) and the
   OBJECT_Map_START marker (21.4, −375.6, 39.3). Touch plate #248 (TOUCH_ONCE, out ch 0x51) sits
   at the spawn [2.62, −377.08, 35.83]-[4.71, −375.69, 37.99] — an arrival plate (SoundTrigger #271
   plays on ch 0x51) [D].
2. The stairwell (StairWell / DOOR_Stairwell_carpark ×3 at (21.5, −377.08, 40.9), (9.1, −377.08,
   95.8), (−2.1, −377.08, 99.1), all doors 0xdb-family with open param 2 = 0 → E-openable) leads
   up one floor to the lobby (y ≈ −368.5) [D placements].
3. The lobby is cut by a **laser grid**: the 0xEB TOUCH triggers named "laser"-family are on 0a —
   on 09 the grid is the SCRIPT_Lasers_ON/OFF/AMBER objects (type 0x31 FuseBox art, placements at
   the origin, positioned by scripts) plus Switch #71 "SCRIPTPLAYER_Lasers" (0x29, ch 0x37 =
   toggle, animation 0x06000627) [D]. The switch's placement transform is the origin (its world
   position is scripted), so the port cannot target it with the use ray; the lasers' physical
   blocking role on this level is presentation (no 0xEB touch triggers on 09 — the survey has none
   outside 0xE8/0xEA/0xEC/0xEF).
4. The **security room** (security_room_new, DOOR_lobby-securityroom at (−26.7, −368.36, 37.4))
   holds a Monitor (0x30, class 0x38): E-use enters the security-camera view [M Monitor_Activate
   0x1b0058] — presentation, writes no channel.
5. **The lift** (lift shaft x ≈ −4.5…−2, z ≈ 10…15, lobby floor): the two 0xE2 SimpleScripts
   LIFTDOORS_LEFT/RIGHT_ENDLEVELDOORS (params (0,64),(1,1),(2,1),(3,57),(4,65535),(6,1)) sit
   closed until **ch 0x39** turns on: SS state 0x40 waits for `SS_Operate()` = 1, which here can
   only come from `switch_channels[57]` (param2 = 1 has no toucher-class bits, param3 = 57) [M
   SS_Create 0x1a9c58, SS_Operate 0x1a9df8, SS_Update 0x1a9948]. When ch 0x39 fires they play
   their open animation (spline, param6 = 1) with sound [M 0x1a9948 state 0x40→1].
6. Inside the lift: TOUCH_ONCE #67 (out ch 0x32) box [−5.01, −369.43, 10.33]-[−2.92, −368.04,
   12.49]; the exit LOAD_LEVEL #63 (next 0x0700000a, gate = ch 0x32, key_gate = 0) fires [D].
   SCRIPTPLAYER_Elevators (#70, mode 64, out ch 0x39, mask 4) plays the 25-tick elevator ride
   script 0x0600059B (entities 0x020005EA/EB = the cab, sound 0x4A1) when activated [D nis dump].

**The exit has two routes** (both through LOAD_LEVEL #63):
- (a) **The elevator route** (completes obj2): activate the elevator system → ch 0x39 → the
  0xE2 lift doors open → walk in → ch 0x32 → 0700000a.
- (b) **The E route**: `Trigger_Activate`'s key gate is param 1 = 0 → no gate: pressing E on the
  Load Point loads 0700000a immediately [M 0x1b2318:76-90] — leaving with obj2 incomplete
  ("Warning: Not all objectives completed" 0x2000021 at mission end [D USATxt]).

## The elevator activation — open question

`SCRIPTPLAYER_Elevators` #70 is E-activatable in the game (mask = 4, SP_Activate's `mask & 4` arm
[M 0x1dc338, Player_Activate 0x1a5170 case class-0 SPs]) but its placement transform is the world
origin (0, 0, 0) [D] — the SP object's use-target in the game comes from its script-animated
matrix (the SP object IS the animated cab; `SP_Update` → `Script_Update` keys obj+0x90). The
port's ScriptPlayers do not model the object-side matrix/collision, so the use ray cannot target
#70. What was tried: every 09 trigger/script/switch/door/fusebox channel list was dumped and none
writes ch 0x39 (trig dump outs 0x32/0x51/0xAB/0x46/0x61; no archive-script Event-0xD writes; the
12 switches read ch 0x37/0x7C/0x7D; doors only read channels [M door.rs +0x66]). Conclusion: the
writer is the SP E-activation itself; the port implements SP E-activation with the SP's placement
matrix as the use target (useobj.rs), which for #70 remains at the origin — the walkthrough drives
ch 0x39 where the game would E-use, and the doc flags this as the one unfaithful spot.

## Failure conditions

- **The alarm** (obj1 inverted): ch 0x61 via the alarm switches → Mission_MonitorObjectives fail
  (FailLabel 0x4000032 "Alarm Raised") → ch 99 → Mission_Update fail end to 0x07000048
  [M 0x1827d8:128-131, 0x182c60].
- Killing a guard: k16 = 0 on every drone → no death channel → no direct fail [D drone-props].
- The exit's cancel channels 0x60–0x63 block the E/load while failing [M 0x1b2318:64-75].

## Not ported / gaps (with the game function)

- **SimpleScript playback** (0xE2 LIFTDOORS_*_ENDLEVELDOORS animation): `SS_Update` 0x1a9948 /
  `SS_Activate` 0x1a9ea8 — 120-fix-explosions owns playback; the port models their channel gate
  (useobj.rs) but not the door-open animation.
- **The SP object matrix** (SP_Update 0x1dbda8 keys obj+0x90): the port's ScriptPlayers have no
  world-object body — the elevator/laser switch use-targets fall back to the placement transform.
- **Monitor camera view** (Monitor_Activate 0x1b0058 / Monitor_Update 0x1afcc8): presentation only.
- **FuseBox shooting** (FuseBox_Update 0x1adfe8): no fused boxes with channels on this level.
- **Switch animations** (the switch SPs Switch_Create 0x1adcc0 attaches): the port toggles the
  channel without the button animation.
